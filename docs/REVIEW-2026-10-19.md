# Code review and refactor notes (2026-10-19)

## Bugs found and fixed

| # | Where | Problem | Fix |
|---|---|---|---|
| 1 | `flash-and-provision.sh --batch` | The CSV was piped into the loop, so the "press Enter" and "retype device" prompts read the *next CSV rows* instead of the keyboard. Batch mode aborted at the first card with "Confirmation did not match". Reproduced. | Rows are read into arrays first; prompts read the terminal. |
| 2 | `flash-and-provision.sh --batch` | Comment, blank and CRLF lines were treated as gateways (the shipped `gateways.csv` ends in a comment block), and `"Seputeh "` (trailing blank) matched no folder. | Shared CSV reader (comments, blanks, `,,,`, BOM, CRLF, quotes, blanks all handled). |
| 3 | `flash-and-provision.sh` | A site folder that did not exist was silently ignored, so a typo gave the card the sample node list. | Missing or empty site folder is now an error (wizard already did this). |
| 4 | `flash-and-provision.sh` | Gateway ID was not validated. `provision.env` is read as root at first boot, so an ID such as `x;reboot` was a command-injection risk. | ID validated (hostname rule) before anything is written. |
| 5 | `flash-and-provision.sh` | Stale `pygw_conf.py` / zip from an earlier site stayed on the card when re-provisioning (`--no-flash`, or a site with fewer files). The `.ps1` already cleaned these. | Provision folder is always cleared first; `provision.env` is written last (as in the `.ps1`). |
| 6 | `flash-and-provision.sh` | `--help` exited 1; a failed copy left the card mounted. | Exit 0; `EXIT` trap unmounts. |
| 7 | wizard `wait_for_card` | If the card vanished during the 1 s settle delay it returned success with an empty list. | Keeps waiting (the `.ps1` already did). |
| 8 | `s3-gateway-firstboot.sh` | `provision.env` was *sourced* as root from a removable card; `set_env_value` broke on values containing `& \| \`. | Read, not sourced (whitelisted keys, CRLF/quotes tolerated); sed-safe writes. |
| 9 | `gateway-site-example.yaml` ("one image per gateway") | Sets `GATEWAY_ID`, but the hook ignored it and first boot then failed with "no provision.env". | Hook bakes `/etc/s3-gateway/provision.env`; first boot uses it when the card has none. |
| 10 | `flash-and-provision.bat` | Saved with bare LF; cmd.exe can mis-handle `goto :label` in such files. | CRLF, plus `.gitattributes` to keep it. |
| 11 | flash log | A relabel row recorded the image name from an earlier flash. | Relabel rows log `none`. |

## Refactor (behaviour unchanged unless listed above)

* New `host/lib/site-files.sh`: node-list rule, site inspection, CSV reader, ID rule were copy-pasted three times (flasher, wizard, `.ps1`); the two Linux scripts now share one copy.
* Flasher and first-boot are split into small functions with a `main` and a source guard (so they can be tested).
* Image hook: pre-flight checks, `.env` edits and unit enabling use helpers/loops. Run against a fake root, the old and new hook produce identical output apart from the first-boot script.
* `.ps1`: one batch-CSV reader for CLI and wizard (was two); `Get-SitePlan` also reports found/missing/usable (the separate `Get-SiteReport` is gone); flash log is parsed once; `Get-Partition` is called once per disk instead of once per guarded path per disk every 2 s.

## Not changed - please decide

* Seputeh site: `site-files/Seputeh/pygw_conf.py` names `samplelisttest.csv`, which is not in the folder (`*.csv` is in `.gitignore`). Cards for s3-gw-89 are correctly refused until it is added.
* `host/site-files/gateways.csv` has `Seputeh ` / `Cheras ` with trailing blanks; harmless now (trimmed), worth cleaning.
* The Linux scripts copy site files byte-for-byte; the `.ps1` converts CRLF/BOM to LF. A CSV saved by Excel on Windows and flashed from Linux keeps CRLF.
* `.ps1` single-card mode only warns (then asks for the disk number) on a missing site folder; Linux now refuses. Left as the original author designed.
* The old build hook had commented-out MQTT broker/user/password values. They are now placeholders; the values remain in git history, so rotate them if the repo is shared.
* `S3_SERVICE_USER` / `S3_DB_NAME` in the yaml look configurable but first boot hard-codes `s3gw` / `serial-gateway-program`.

## How it was checked

`bash -n` on every script; flasher run against stubbed mount/block device (single, batch, bad CSV, bad site, `--no-flash` relabel); first boot with a hostile `provision.env`; wizard driven end-to-end with a fake card; old vs new image hook diffed on a fake root; PowerShell 7 parse plus unit/wizard tests with stubbed Storage cmdlets. **Not run:** the real disk-writing path on Windows and Linux, and a real image build.
